### 0.2 화면 이동

```
            ┌──────────── 상단 내비게이션 (모든 화면) ────────────┐
            │ 대시보드 · 통계 · 공고 등록 · 분석한 공고 ·            │
            │ 기본 이력서 · 가져오기 · 사이트 반영(배지) · 설정      │
            └──────────────────────────────────────────────────────┘

대시보드 ──행 클릭(공고 있음)──▶ 공고 상세
   │      └행 클릭(가져온 기록)─▶ 그 자리에서 행 펼침(상태 변경)
   ├─[공고 등록]──────────────▶ 공고 등록 ──등록──▶ 공고 상세(분석 진행 표시)
   ├─"분석한 공고 N건 보기"────▶ 분석한 공고 ──행 클릭──▶ 공고 상세
   └─"통계 보기 →"────────────▶ 통계(사이트·기간 필터를 넘김)

공고 상세 ─[인쇄용 보기]──▶ 면접 준비 인쇄용(새 탭)

분석 실패(로그인 필요 사이트) ─안내 링크──▶ 설정(사이트 로그인)
```

### 0.3 상단 내비게이션 (모든 화면 공통)

| 항목 | 설명 |
|---|---|
| 앱 이름 "Career Flow" | 누르면 대시보드 |
| 대시보드 / 통계 / 공고 등록 / 분석한 공고 / 기본 이력서 / 가져오기 / 설정 | 각 화면 링크. 현재 화면 강조 |
| 사이트 반영 **(5단계)** | 링크 + **미완료 사이트 수 배지**(0이면 배지 없음) |
| 진행 중 작업 표시 | AI 작업이 돌고 있으면 "작업 1개 진행 중" 작은 표시. 누르면 그 작업의 공고/화면으로 이동. 작업은 한 번에 하나씩 실행되므로(기획서 9.3) 대기 중 작업이 있으면 "대기 2" 함께 표시 |

### 0.4 공통 요소

화면 여러 곳에서 같은 모양·동작으로 쓰는 요소.

**작업 진행 표시 (`JobStatus`)** — AI 작업(분석, 맞춤 이력서, 면접 준비, 가져오기, 사이트 반영)이 걸린 자리에 표시.

| 작업 상태 | 표시 | 버튼 |
|---|---|---|
| 대기 | "앞의 작업이 끝나면 시작합니다 (대기 N번째)" | 없음 |
| 실행 중 | 작업별 문구 + 예상 시간 + 경과 시간(예: "분석 중… 보통 1~2분 · 0:47") | 없음 |
| 완료 | 결과가 있는 화면을 자동 새로고침 | — |
| 실패 | 아래 실패 종류별 문구 | `[다시 시도]` |

- 화면은 2초마다 작업 상태를 조회한다.
- 작업별 진행 문구:
  - 분석: "분석 중… (보통 1~2분)"
  - 맞춤 이력서: "맞춤 이력서 작성 중… 보통 1~3분"
  - 면접 준비: "회사 조사와 면접 준비 중… 보통 3~8분"
  - 사이트 반영: "반영할 내용 정리 중…"

**실패 종류별 문구** (모든 AI 작업 공통)

| 실패 종류 | 문구 | 버튼·추가 입력 |
|---|---|---|
| 본문 추출 실패 (공고 분석만) | "공고 본문을 읽지 못했습니다. 공고 페이지 내용을 복사해 붙여넣어 주세요." 로그인이 필요한 사이트면 "설정 → 사이트 로그인에서 한 번 로그인하면 다음부터 자동으로 읽습니다" 링크 추가 | 붙여넣기 입력창 + `[이 내용으로 분석]` |
| Claude Code 로그인 안 됨 | "Claude Code 로그인이 필요합니다. 터미널에서 `claude`를 실행해 로그인한 뒤 다시 시도하세요." | `[다시 시도]` |
| 사용 한도 도달 | Claude Code가 준 메시지 원문 그대로 | `[다시 시도]` |
| 시간 초과 | "시간 제한(N분)을 넘었습니다. 설정에서 시간 제한을 늘릴 수 있습니다." | `[다시 시도]` |
| 결과 형식 오류 | "결과를 읽지 못했습니다." + [원문 보기] 펼침 | `[다시 시도]` |
| 앱 재시작으로 중단 | "앱이 종료되어 작업이 중단되었습니다." | `[다시 시도]` |
| 그 밖의 오류 | 오류 메시지 | `[다시 시도]` |

**배지**

| 배지 | 값 |
|---|---|
| 상태 배지 | 분석함 / 지원 / 서류합격 / 과제·코딩테스트 / 면접 N차 / 최종합격 / 불합격 / 지원취소 |
| 사이트 표시 | 리멤버 / 원티드 / 그룹바이 / 잡코리아 / 홈페이지 지원 / 기타. **사이트마다 색이 다르다**(색 점 + 이름, 색 값은 `docs/design/design.md`). 상태 배지(채운 알약)와 모양으로도 구분된다 |
| 적합도 | 0–100 숫자. 분석이 없으면 "–" |

**확인 알림** — 저장·등록 같은 동작이 끝나면 화면 위쪽에 잠깐 뜨는 한 줄 알림(예: "지원 완료로 저장했습니다").

### 보기 전환 (Notion 데이터베이스 보기 방식)

제목 아래에 보기 탭 4개를 둔다. 검색과 필터는 모든 보기에 똑같이 적용된다. 선택한 보기는 주소(`?view=`)에 남아 다음에 열 때도 유지된다.

| 보기 | 모양 | 내용 |
|---|---|---|
| 전체 | 표 | 아래 "지원 목록 표" |
| 사이트별 | 접히는 묶음 | 사이트마다 묶음 하나(색 이름표 + 개수). 펼치면 그 사이트의 지원 표. 묶음 머리 오른쪽에 **서류 통과율** |
| 상태별 | 보드(열 6개) | 지원 / 서류합격 / 과제·코딩테스트 / 면접 / 최종합격 / 불합격·지원취소. 6열이 한 화면에 들어가게 열 최소 너비는 150px. 카드에 회사, 포지션, 사이트, 면접 차수, 지원일, 적합도. 카드를 다른 열로 끌어 놓으면 상태 변경 창(3.8)이 열리고, 저장해야 바뀐다 |
| 이력서별 | 접히는 묶음 | 제출한 이력서로 묶는다. 순서: **"맞춤 이력서"**(맞춤본으로 낸 기록 전부, 3단계) → "기본 서류 {직무}"(키트 기본 서류 그대로, 3단계) → "기본 v{n}"(3단계 전 [지원 완료] 기록, 번호 큰 순) → 이력서 파일("이력서 2026-09-05", 기획서 7.9, 날짜 늦은 순) → 마지막 "모름". 묶음 머리에 개수와 서류 통과율. 통계 화면 "서류 버전별"(이력서)과 같은 묶음이다 |

- 서류 통과율은 통계 화면(10장)과 같은 정의를 쓴다(D-18, 기획서 7.10).
  - 서류 통과율 = 통과 ÷ (통과 + 불합격 + 무응답)
  - 통과: 서류합격을 거친 기록이다. 지금 상태가 서류합격, 과제·코딩테스트, 면접, 최종합격 중 하나이거나 이력에 있는 것으로, 그 뒤 불합격·지원취소도 포함한다.
  - 무응답: 지원 후 30일이 지나도 지원 상태인 기록이다.
  - 30일이 안 된 지원(대기)과 지원취소는 분모에서 뺀다.
- 묶음 머리 문구는 `서류 통과 9 / 469 · 1.9%`다.
  - 분모가 0이면 "결과 대기", 1~4면 비율 대신 "표본 부족 (n=3)", 5~19면 비율 옆에 "표본 적음" 배지를 단다.
  - 어느 사이트, 어느 이력서 버전이 결과가 좋았는지 비교하는 용도다. 자세한 비교는 통계 화면에서 한다.
- 사이트별·이력서별 묶음은 **기본으로 접혀** 머리(이름·건수·통과율)만 보인다. 누르면 펼치고, 펼친 묶음은 이 브라우저에만 기억한다.
- **페이지 나누기**(요약 줄·통계 숫자와 묶음 머리의 건수·통과율은 늘 전체 기준)
  - 전체 보기: 한 페이지 50건. 표 아래에 "전체 n건 중 a–b"와 페이지 번호(처음·이전·번호·다음·마지막). 주소의 `page`로 나타내고(1페이지는 생략) 검색·필터·보기와 함께 유지된다. 필터·검색·보기가 바뀌면 1페이지로 간다. 범위를 벗어난 page는 마지막 페이지로 본다.
  - 묶음 보기(사이트별·이력서별): 펼친 묶음에 처음 20건과 "n건 더 보기". 누르면 그 묶음의 전부가 보인다(주소의 `more`).
  - 상태별 보드: 열마다 처음 20장과 "n장 더 보기".
  - 기록 상세(메모·제출 서류·이력)는 보이는 행만 읽는다.
- 날짜 입력은 모두 `YYYY-MM-DD` 텍스트 칸 + 오른쪽 달력 버튼이다(숫자만 쳐도 하이픈이 들어가고, 잘못된 날짜는 등록을 막는다). 브라우저 기본 date 입력은 한국어 Windows에서 빈 요일 칸이 "2026-11-20 ()"로 보여 쓰지 않는다.

| 가져온 기록 표시 | 공고 없이 "지원 기록만" 있는 행(가져오기로 들어온 것)은 회사명 옆에 작은 "기록만" 표시 |

### 버튼·입력

| `[상태 ▾]` | 전체 / 지원 / 서류합격 / 과제·코딩테스트 / 면접 / 최종합격 / 불합격 / 지원취소 중 하나. **서류합격, 과제·코딩테스트, 면접, 최종합격은 그 단계를 거친 기록을 모두 보여 준다**(지금 상태가 그 뒤 단계이거나, 상태 이력에 그 단계 이상이 있는 기록. 예: 서류합격 뒤 불합격). 과제·코딩테스트를 거친 기록은 서류합격 필터에도 나온다. 면접·최종합격 기록은 과제·코딩테스트 필터에 나오지 않는다(과제를 거쳤다는 이력이 있을 때만). 지금 상태가 지원이면 거친 것으로 치지 않는다. 지원·불합격·지원취소는 지금 상태 기준. 이 네 단계 중 하나를 고르면 아래에 "이 단계를 거친 기록을 모두 보여 줍니다(지금 상태와 관계없이)". 상태별 보드의 칸은 지금 상태 기준 그대로다 |
| `[사이트 ▾]` | 전체 / 리멤버 / 원티드 / 그룹바이 / 잡코리아 / 홈페이지 지원 / 기타 |
| `[기간 ▾]` | 전체 / 이번 달 / 최근 3개월 / 최근 1년 / 직접 지정(시작일~종료일)  |
| `[+ 공고 등록]` | 공고 등록 화면으로 이동 |
| "분석한 공고 N건 보기" | 분석한 공고 화면으로 이동 |
| "통계 보기 →" | 통계 화면(10장)으로 이동. 지금 고른 사이트와 기간을 넘긴다. 기간이 "이번 달"이면 기간은 넘기지 않는다(통계 화면에는 "이번 달"이 없다) |
| 행 클릭 (공고 있음) | 그 공고 상세로 이동 |
| 행 클릭 (기록만) | 행 아래가 펼쳐지며 **상태 변경**(상태 선택, 면접이면 차수, 날짜 기본 오늘, 메모) + `[저장]`, 상태 이력 목록, 메모 편집, 제출 서류(5.5 "제출 서류 표시", [보기]), `[기록 수정]`(3.10 창), `[기록 삭제]`(확인 창) |

## 2. 공고 등록 `/postings/new`

**목적**: 공고 링크를 넣으면 바로 분석을 시작한다.

```
공고 링크  [ https://www.wanted.co.kr/wd/12345            ]  [등록하고 분석]

▸ 링크가 안 열리면: 공고 본문 직접 붙여넣기
  [ 여러 줄 입력 ...                                    ]
```

| 요소 | 동작 |
|---|---|
| 공고 링크 입력 | URL 한 줄. 사이트는 주소로 자동 판별(리멤버/원티드/그룹바이/잡코리아, 그 외는 기타) |
| 출처 이름 | 기타로 판별되거나 본문만 넣을 때 나타난다(선택). 예: 회사 채용 페이지, 지인 추천. 전에 쓴 이름 자동완성 |
| "공고 본문 직접 붙여넣기" 펼침 | 여러 줄 입력. 링크와 함께 넣어도 되고 본문만 넣어도 된다(링크 없는 공고: 지인 추천 등) |
| `[등록하고 분석]` | 링크·본문 둘 다 비었으면 비활성. 누르면 공고를 만들고 분석 작업을 걸고 **공고 상세로 이동**(상세에서 진행 표시) |
| 이미 등록된 링크 | 새로 만들지 않고 기존 공고 상세로 이동 + 알림 "이미 등록된 공고입니다". 추적용 꼬리(`?utm_...`, `#...`)가 달라도 같은 공고로 본다 |

**상황별 표시**
- 기본 이력서가 없으면: 입력은 가능하되 등록 버튼 위에 "기본 이력서가 없어 분석이 실패합니다. 먼저 등록하세요 → 기본 이력서" 경고.

## 3. 공고 상세 `/postings/[id]`

**목적**: 공고 하나에 관한 모든 것(분석, 맞춤 이력서, 면접 준비, 원문, 지원 기록)을 한 화면에 모은다.

### 3.1 상단 (탭과 무관하게 항상 보임)

```
토스 [변경]   Server Developer        원티드 · 마감 2026-12-01 · 등록 11/16   [원본 공고 열기 ↗]

⚠ 이 회사에 지원한 기록이 있습니다
   · 2025-10-03 원티드 'Server Developer' (서류합격)
   · 2025-03-02 잡코리아 'Platform Engineer' (불합격)

[지원 완료]                                 ← 지원 전
상태: 면접 2차  [상태 변경 ▾]                ← 지원 후
```

| 요소 | 내용·동작 |
|---|---|
| 회사명 | 분석이 정한 회사(분석 전에는 "분석 후 표시"). 옆 `[회사 연결 변경]` → 작은 창: (1) 기존 회사 검색해서 연결 바꾸기, (2) 이 회사에 **별칭 추가**(예: "비바리퍼블리카"에 "토스" 추가), (3) **다른 회사와 합치기**: 합칠 회사를 검색해 고르면 "A와 B를 합칩니다. 공고 n건, 지원 기록 n건이 A로 모입니다" 확인 후 합친다 |
| `[공고 삭제]` | 지원 기록이 없는 공고에만 보인다. 확인 창 "이 공고와 분석 결과, 맞춤 이력서, 면접 준비를 삭제합니다" → 삭제 후 대시보드로 이동. 작업이 실행 중이면 "작업이 끝난 뒤 삭제하세요" |
| 포지션·사이트·마감일·등록일 | 분석 결과에서 읽은 값. 마감일 없으면 "상시" |
| `[원본 공고 열기 ↗]` | 원래 URL을 새 탭으로(링크 없는 공고는 숨김) |
| **중복 경고 배너** | 같은 회사(별칭·법인명 포함)에 이 공고 말고 다른 지원 기록이 있으면 노란 배너. 건마다 지원일·사이트·포지션·상태. 각 줄을 누르면 그 공고(있으면)로 이동 |
| `[지원 완료]` | 지원 전에만 보임. 분석이 끝나기 전에는 비활성 + "분석이 끝난 뒤 누를 수 있습니다". 누르면 3.7의 지원 완료 폼 |
| 상태 + `[상태 변경 ▾]` | 지원 후에만 보임. 3.8 참고 |

### 3.2 탭

| 순서 | 탭 | 생기는 단계 |
|---|---|---|
| 1 | 분석 | 1·2단계 |
| 2 | 맞춤 이력서 | 3단계 |
| 3 | 면접 준비 | 4단계 |
| 4 | 공고 원문 | 1·2단계 |
| 5 | 지원 기록 | 1·2단계 |

- 처음 열면 "분석" 탭. 선택한 탭은 주소(`?tab=`)에 남긴다.
- 탭 이름 옆에 상태 점: 해당 작업이 진행 중이면 "…", 실패면 "!".

### 3.3 분석 탭

**링크로 읽기 실패 (D-08)**: 원티드처럼 자동 읽기를 막는 사이트가 있다. 그래서 본문 추출 실패를 예외가 아닌 기본 흐름으로 보이게 한다.
- 큰 안내: "이 사이트는 자동으로 읽을 수 없습니다. 공고 페이지에서 본문을 복사해 붙여넣어 주세요."
- [공고 페이지 열기 ↗]: 평소 쓰는 브라우저의 새 탭으로 연다.
- 단계 안내 3줄: ① 페이지 열기 ② Ctrl+A, Ctrl+C ③ 아래에 붙여넣기
- 붙여넣기 입력창과 [이 내용으로 분석]은 처음부터 펼쳐 둔다.
- 화면이 보이는 브라우저로 다시 시도하는 방식은 쓰지 않는다.

**진행 중·실패**: 0.4의 작업 진행 표시 / 실패 종류별 문구. 본문 추출 실패 시 이 탭에 붙여넣기 입력창이 바로 뜬다.

**결과**

```

항목별      필수 요건 85 · 우대 사항 70 · 경력 연차 90 · 기술 스택 80 · 도메인 75 · 희망 조건 90
            (각 항목 펼치면 근거 한두 줄)

            주요 업무 / 필수 요건 / 우대 사항 / 기술 스택 (목록)

부족한 점
  이력서에서 보완 가능   · Kafka 운영 경험 — 프로젝트 B에 있으나 이력서에 안 드러남 → 맞춤 이력서에서 강조
  실제로 부족            · Kotlin 실무 — 면접에서 학습 계획으로 답변 준비

[다시 분석]
이전 분석   11/16 14:02 · 82 (현재) │ 11/10 09:30 · 76 (v2 기준)   ← 누르면 그 결과 보기
```

| 데이터 | 설명 |
|---|---|
| 적합도 점수 | 0–100 큰 숫자 |
| 기준 이력서 버전·분석 시각 | "기본 이력서 v3 기준". 현재 기본 이력서가 더 새 버전이면 "기본 이력서가 v4로 바뀌었습니다 — 다시 분석하면 반영됩니다" 안내 |
| 항목별 점수·근거 | 필수 요건 / 우대 사항 / 경력 연차 / 기술 스택 / 도메인 / 희망 조건(희망 조건이 비어 있으면 이 항목 없음) |
| 공고 요약 | 경력 요건, 고용 형태, 근무지, 마감일, 연봉 정보, 주요 업무, 필수 요건, 우대 사항, 기술 스택 |

### 3.4 맞춤 이력서 탭 **(3단계)**

계획: [../plans/phase-3-tailored-resume.md](../plans/phase-3-tailored-resume.md) Task 7·3b·9 (재설계 1·2: **프로필 방식**, D-26·D-28 b). 배치는 와이어프레임 3-5. 목업의 "맞춤 이력서" 탭은 재설계 전 모양이라 색·글꼴만 참고한다.

맞춤본은 사용자가 올린 **서류 키트**(5.6)의 기본 서류(직무별 이력서·경력기술서)에 프로필 레시피를 적용해 만든다. 앱 안 기본 이력서(5.2)는 쓰지 않는다(공고 분석용).

**상황별 표시**

| 상황 | 표시 |
|---|---|
| 서류 키트 없음 | "맞춤 이력서는 서류 키트(가이드·기본 서류·마스터스토리)로 만듭니다. 먼저 키트를 올리세요." + `[서류 키트로 →]`(`/resume?tab=kit`) |
| 키트에 오류 | "서류 키트에 오류가 있어 만들 수 없습니다(오류 n건)." + `[서류 키트로 →]`. 오류 없는 이전 키트가 있으면 그 키트로 진행하고 맨 위에 "가장 최근 키트에 오류가 있어 이전 키트(v…)를 씁니다" |
| 맞춤본 없음 | **프로필 고르기** 상자(아래). 분석 전이어도 공고 본문이 있으면 고를 수 있다(그때는 단어 수 기준 추천) |
| 분석 중 | 프로필 고르기 상자 위에 "분석이 끝나면 AI 추천이 보입니다" + 0.4 분석 진행 표시. 그동안 단어 수 기준으로 골라 만들 수 있다 |
| 용어 맞추는 중·다듬는 중 | 탭 맨 위에 0.4 작업 진행 표시("공고 용어 맞추는 중… (보통 1~3분)" / "맞춤 이력서 다듬는 중… (보통 1~3분)"). 아래에는 지금 리비전. 버튼·입력은 비활성 |
| 실패 | 탭 맨 위에 0.4 실패 문구 + `[다시 시도]`. 이전 리비전은 그대로 |
| 키트가 바뀜 | 고른 리비전의 키트 ≠ 지금 쓰는 키트면 "이 맞춤본은 키트 {이전 버전} 기준입니다. 지금 키트는 {버전}입니다." + `[새 키트로 다시 조립]`(같은 직무·프로필·추가 조정) |

**프로필 고르기** (맞춤본이 없을 때, 그리고 결과 화면의 `[프로필 바꾸기]`)

```

추가 조정
  [✓] Kafka·메시지 큐·비동기·이벤트   추천 · Kafka      ← AI가 추천하면 미리 체크
  [ ] CI/CD·AWS·DevOps
                                        [맞춤본 만들기]   보통 1초. AI를 쓰지 않습니다.
```

- 추천도는 공고 분석(AI)이 프로필마다 따로 매긴 0~100%다(합이 100이 아니다, D-28 b). 근거 키워드는 공고 본문에 실제로 있는 단어만, 이유는 한 줄. 1등에 "추천"(같으면 기본 프로필). 프로필·추가 조정 목록과 이름은 키트 가이드에서 읽은 그대로다.
- 직무를 바꾸면 그 직무의 프로필이 추천도 순으로 바뀐다(분석이 모든 직무를 매기지 않았으면 그 직무는 단어 수 기준).
- AI 추천을 쓸 수 없을 때
  - 분석이 키트 없이 됐거나 키트를 분석 뒤에 올렸거나 옛 분석이면: 제목이 "단어 수 기준 추천 (AI 추천 아님)", 막대 대신 일치 단어 수. `[AI 추천 받기 (다시 분석)]` — 공고를 다시 분석한다(보통 1~2분, 적합도도 새로 매겨지고 이전 분석은 기록에 남음).
  - 추천이 이전 키트 기준이면: "이전 키트(v4) 기준 추천" + 같은 버튼. 지금 키트에 없는 프로필은 빼고 보인다.
- `[맞춤본 만들기]` → 바로 r1(조립본)이 생기고 결과 화면으로 바뀐다(작업 큐 없음).

**이력서 작업 공간에 요청** (D-26 추가, D-30 추천안·결정 대기)

앱 조립·용어 맞추기로 부족해 보일 때, 사용자가 이력서를 만드는 자기 Claude 작업 공간에 "이 공고용 이력서"를 요청하고 결과를 앱에 다시 넣는다. 앱은 그 작업 공간을 실행하거나 그 폴더에 쓰지 않는다.

```
ⓘ 이력서 작업 공간에 요청해 볼 만합니다: 추천도가 60% 미만 · 확인 필요 1건 · 남은 추가 조정 1건
   [요청문 복사] [요청문 받기 (.md)]   작업 공간(Claude Code)에 붙여 넣으세요.
   만든 뒤 → [결과 올리기]  이력서.md · 경력기술서.md
```

| 요소 | 동작 |
|---|---|
| 권유 줄 | 아래 중 하나라도 맞으면 결과 화면 맨 위(경고 상자 아래)에 보인다: ① 분석 추천도 1등이 60% 미만 ② 용어 맞추기·다듬기 뒤에도 "확인 필요"가 남음 ③ 남은 추가 조정이 있음 ④ AI가 "허용 범위 안에서는 잘 맞추기 어렵다"고 표시. 이유를 줄에 나열한다 |
| `[작업 공간에 요청 ▾]` | 권유 줄이 없어도 결과 화면 아래 버튼 줄에 늘 있다. 메뉴: 요청문 복사 / 요청문 받기 / 결과 올리기 |
| 요청문 | 지원 폴더 이름 제안({지원 예정일}_{회사}_{직무}), 공고 정보, 공고에서 많이 나온 단어, 고른 직무·프로필·추가 조정(추천도 순위), 앱 조립 요약·남은 추가 조정, 자동 검사에서 걸린 것, 메모 칸(요청 전에 입력 가능), 공고 본문 전문, 맺음말("작업 공간의 가이드·작성 규칙·마스터스토리를 따라 이력서.md·경력기술서.md를 만들어 주세요. 마스터스토리 밖의 사실·숫자는 쓰지 않습니다") |
| `[요청문 복사]` | 클립보드로. "복사됨" 잠깐 표시 |

**글자 잘림 방지** (디자인 B, 페이지 폭 1440, 한글 줄바꿈 규칙 `word-break: keep-all`)
- 폭 1100px 이상: 두 칸(`minmax(0,1fr) 360px`), 미리보기는 오른쪽에 붙어 따라온다(sticky). 그보다 좁으면 한 칸, 미리보기는 맨 아래(최대 420px).
- 프로필 고르기: 프로필 이름 칸 최소 140px, 일치 단어는 줄바꿈 허용. 프로필 줄·리비전 선택은 좁으면 두 줄로 내려간다(`flex-wrap`). 내려받기 버튼은 줄바꿈하지 않고 버튼 단위로 다음 줄로 간다.
- 공백 없는 긴 영문·주소는 칸 안에서 줄바꿈한다(`overflow-wrap: anywhere`). 한글 낱말은 중간에서 끊지 않는다.
- 리비전 select는 칸 너비를 넘지 않는다(`max-width: 100%`). 요청 전문은 select 밖 "요청:" 줄에 쓴다.
- PDF와 미리보기 HTML에도 같은 줄바꿈 규칙을 쓴다.

### 3.5 면접 준비 탭 **(4단계)**

**준비 없음**: "회사 조사(웹 검색)와 예상 질문을 만듭니다. 보통 3~8분 걸립니다." + 차수 입력(기본 "1차", 지원 상태가 "면접 2차"면 "2차") + `[면접 준비 만들기]`. 분석 전이어도, 지원 전이어도 만들 수 있다.

**진행 중·실패**: 0.4 공통.

**결과**

```
차수  (1차) (2차 임원)  [+ 새 차수]          리비전 [r2 · "Kafka 질문 더" ▾]   [인쇄용 보기 ↗]

팀의 과제    · …
내가 기여할 점 · …
예상 질문    [기술] [경력·프로젝트] [인성·협업] [회사·지원동기]
             ▸ Kafka 파티션 수는 어떻게 정했나요?
               나올 이유: … / 답변 소재: … / 관련 이력서 항목: 프로젝트 B
부족한 점 대응  · Kotlin 실무 — …
역질문         · …
체크리스트     ☐ 최근 투자 뉴스 읽기  ☐ 기술 블로그 결제 글 2편 …
출처           · 기사 제목 ↗ · …

추가 요청  [ 예: "기술 질문을 Kafka 중심으로 더"   ]  [요청]
```

| 데이터 | 설명 |
|---|---|
| 차수 칩 | 이 공고의 면접 준비 차수 목록. 선택한 차수의 내용 표시 |
| 리비전 선택 | 맞춤 이력서 탭과 같은 방식 |

### 3.7 지원 완료 폼 (`[지원 완료]`를 누르면 뜨는 작은 창)

| 입력 | 기본값 |
|---|---|
| 지원일 | 오늘 |
| 지원 사이트 | 공고의 사이트 (리멤버/원티드/그룹바이/잡코리아/홈페이지 지원/기타 중 변경 가능) |
| 출처 이름 | 사이트가 기타일 때만 보인다. 기본: 공고의 출처 이름. 전에 쓴 이름을 고를 수 있다 |
| 제출 서류 **(3단계, D-23)** | 아래 "제출 서류 칸" |
| 메모 | 비어 있음 |

**제출 서류 칸** (지원 완료 창과 3.10 수정 창 공통). 종류 이름은 select 왼쪽 라벨로 한 번만 쓴다(6.2 직접 입력 표와 같은 모양).

| 칸 | 선택지 | 기본값 |
|---|---|---|
| 이력서 | 이 공고의 맞춤 리비전들(`맞춤 이력서 r3 · B3 정합성`, 최신순) → 기본 서류(`기본 서류 백엔드 · B1`, 키트의 직무마다, 사이트에 등록한 이력서나 기본 PDF로 냈을 때) → 이력서 파일 날짜(늦은 순) → `모름` | 맞춤본이 있으면 최신 맞춤 리비전. 없고 키트가 있으면 추천 직무의 기본 서류. 키트도 없으면 지원일 기준 이력서 파일, 없으면 모름 |
| 경력기술서 | `모름` · `없음` · 파일 날짜(늦은 순) | 지원일 기준 파일(7.9 규칙. 가장 이른 파일보다 앞서면 없음) |
| 포트폴리오 | 경력기술서와 같음 | 경력기술서와 같음 |

- 지원일을 고치면 직접 고르지 않은 칸만 다시 골라진다. 이력서 칸이 맞춤본이면 그대로 둔다.
- 맞춤본(첨부 PDF·홈페이지 지원)은 "맞춤 이력서 r번호", 사이트에 등록해 둔 기본 이력서로 냈으면 "기본 서류 {직무}"를 고른다. 통계의 "맞춤 이력서 효과"와 "프로필별"(10.3)이 이 값으로 센다.
- 기본값 그대로 `[저장]`만 눌러도 된다(입력이 늘지 않게).
- 서류 파일이 하나도 없으면 칸 아래 "서류 파일이 없어 이력서는 '모름'입니다 → 서류 파일" 링크.

`[저장]` → 관리 목록(대시보드)에 추가, 상단이 "상태: 지원"으로 바뀌고 지원 기록 탭에 첫 줄 생성. `[취소]`.

**다시 지원할 때 확인 창 (D-10)**: [지원 완료]를 누르면, 최근 6개월 안에 **같은 공고나 같은 회사**에 지원한 기록이 있는지 먼저 본다.
- 있으면 지원 완료 폼 대신 확인 창을 먼저 띄운다.
  - 제목: "최근 6개월 안에 지원한 기록이 있습니다"
  - 본문: 기록마다 지원일, 사이트(색), 포지션, 현재 상태를 한 줄씩 보여 준다. 같은 공고 기록은 "이 공고"로 표시한다.
  - 버튼: [취소], [그래도 지원 완료]. [그래도 지원 완료]를 누르면 지원 완료 폼으로 넘어간다.
- 6개월이 지난 기록만 있으면 확인 창 없이 바로 폼을 띄운다.
- 이미 지원한 공고에도 상단에 [다시 지원 완료] 버튼이 남는다. 지원 기록 탭에는 이 공고의 지원 기록을 모두 최신순으로 보여 준다.

## 5. 기본 이력서 `/resume`

**목적**: 모든 분석·맞춤 이력서의 기준이 되는 이력서 하나를 등록·편집하고, 버전을 관리하고, 희망 조건을 적는다.

화면 안 구역: **이력서 편집** / **버전 기록** / **희망 조건** / **서류 파일**(5.5) / **서류 키트**(5.6, 3단계) (탭 또는 세로 구역, 구현자 재량). 이 화면의 기본 이력서는 공고 분석의 기준이다. 맞춤 이력서는 서류 키트로 만든다.

### 5.1 처음 등록 (이력서가 없을 때)

```
기존 이력서를 올려 시작하세요.
[파일 선택] 이력서.pdf, 경력기술서.docx, 포트폴리오.pdf   (PDF·DOCX·TXT·MD, 파일당 20MB까지)
또는 텍스트 붙여넣기 [ ...                                  ]
[가져오기]
```

1. `[가져오기]` → 작업 진행 표시("이력서를 항목별로 정리 중…").
2. 끝나면 편집기에 결과가 채워진 **저장 전 검토** 상태: 상단에 "아직 저장되지 않았습니다. 내용을 확인하고 저장하세요." + `[기본 이력서로 저장]`.
3. 저장하면 v1.

| 상황 | 표시 |
|---|---|
| 파일·텍스트 둘 다 없음 | `[가져오기]` 비활성 |
| 지원하지 않는 파일·20MB 초과 | 파일 옆에 사유 표시, 그 파일은 제외 |
| 가져오기 실패 | 0.4 공통 + "직접 입력으로 시작" 버튼(빈 편집기) |

### 5.2 이력서 편집

현재 버전 번호(예 "v3 · 11/16 저장")를 위에 표시. 섹션별로 편집:

| 섹션 | 항목 | 편집 동작 |
|---|---|---|
| 기본 정보 | 이름, 이메일, 전화, 링크(이름+URL 여러 개) | 링크 추가·삭제 |
| 한 줄 소개 | 여러 줄 텍스트 | |
| 경력 | 회사, 직무/직급, 시작(YYYY-MM), 종료(YYYY-MM 또는 "재직 중"), 담당 업무, 성과(문장 여러 개) | 경력 추가·삭제·순서 이동, 성과 문장 추가·삭제·순서 이동 |
| 프로젝트 | 이름, 소속, 기간, 역할, 사용 기술(여러 개), 성과(여러 개), 링크 | 추가·삭제·순서 이동 |
| 기술 스택 | 분류 이름 + 기술 목록 | 분류 추가·삭제, 기술 추가·삭제 |
| 학력 | 학교, 전공, 학위, 기간 | 추가·삭제 |
| 자격증·수상·교육 | 이름, 발급처, 날짜 | 추가·삭제 |
| 경력기술서 | 긴 본문 | |
| 포트폴리오 | 제목, 링크 또는 파일, 요약 | 추가·삭제 |

| 버튼 | 동작 |
|---|---|
| `[저장]` | "변경 메모"(선택, 예 "B 프로젝트 성과 추가") 입력 후 저장 → 새 버전(v4). 내용이 이전 버전과 같으면 버전을 만들지 않고 "바뀐 내용이 없습니다" |
| 저장 후 안내 **(5단계)** | 내용이 바뀌었으면 "4개 사이트에 반영할 내용을 정리하고 있습니다 → 사이트 반영" 링크 |
| (없음) | 앱 기본 이력서의 PDF 받기는 만들지 않는다(재설계 1, D-26 a). 실제 서류 PDF는 서류 키트(5.6)의 기본 서류에서 나온다. 앱 기본 이력서는 공고 분석의 기준으로만 쓴다 |
| 저장하지 않고 떠나기 | "저장하지 않은 변경이 있습니다" 확인 |

### 5.5 서류 파일 (`/resume?tab=docs`) — 기획서 7.9, D-15

지난 지원에 낸 서류 파일(이력서·경력기술서·포트폴리오 PDF) 목록. 앱 기본 이력서의 버전(5.3)과는 별개다. 등록·삭제 버튼은 없다. 폴더를 읽어 그대로 보여 준다.

```
서류 파일
data\documents\resume·career·portfolio 폴더에 이력서_YYYYMMDD.pdf 형식으로 넣으면 여기에 나옵니다.

이력서       2026-11-02   기록 3건   [보기]
             2026-10-17   지원 5건   [보기]
             2026-09-05   지원 0건   [보기]
경력기술서   2026-11-02   …          [보기]
포트폴리오   2026-10-17   …          [보기]
             2026-07-22   …          [보기]

메모에 "제출 서류" 줄이 있는 기록 42건          [메모의 제출 서류 옮기기]
```

| 요소 | 동작 |
|---|---|
| 목록 | 종류별 묶음, 날짜 늦은 순. 행마다 날짜, 이 파일을 쓴 지원 기록 수 |
| `[보기]` | 새 탭에서 PDF를 연다(`/api/documents/<파일 이름>`) |
| 규칙 밖 파일 | 폴더에 이름 규칙에 맞지 않는 파일이 있으면 목록 아래 "이름 규칙에 맞지 않아 쓰지 않는 파일: {이름들}"(회색) |
| 이관 줄 | 메모에 "제출 서류: …" 줄이 있고 제출 서류 칸이 비어 있는 기록이 있을 때만 보인다. `[메모의 제출 서류 옮기기]` → "{n}건의 제출 서류를 옮겼습니다", 건너뛴 기록이 있으면 "{n}건은 폴더에 없는 파일({이름들}) 때문에 옮기지 않았습니다" |

| 상황 | 표시 |
|---|---|
| 파일 0개 | 종류 카드마다 "파일이 없습니다." + 위 안내 문구 |
| 데이터 폴더에 `documents` 폴더가 없음 | 앱 시작 시 만든다(빈 폴더) |

**제출 서류 표시** (대시보드 기록만 행 펼침, 3.9 지원 기록 탭에서 공통)

```
제출 서류   이력서      2026-11-02  [보기]
            경력기술서  없음
            포트폴리오  2026-07-22  파일 없음
```

- [보기]는 새 탭에서 PDF를 연다. 파일이 폴더에서 없어졌으면 [보기] 대신 회색 "파일 없음".
- 종류 값은 셋 중 하나다: 파일(날짜 + [보기]) / **"없음"**(내지 않음, 경력기술서·포트폴리오만) / **"모름"**(회색, 어느 파일인지 모름). "없음"은 회색이 아닌 보통 글자로 써서 "모름"과 구별한다. [보기]는 없다.
- 셋 다 모름이면 "제출 서류  모름" 한 줄. "없음"이 하나라도 있으면 세 줄로 쓴다(예: 이력서 모름 / 경력기술서 없음 / 포트폴리오 없음).
- **(3단계)** 맞춤본으로 낸 기록은 이력서 줄이 `이력서  맞춤 이력서 r2  [보기]`, 기본 서류로 낸 기록은 `이력서  기본 서류 백엔드  [보기]`다. [보기]는 그 이력서 PDF를 다시 만들어 새 탭에 연다. 맞춤본·키트 PDF는 서류 파일 목록(위)에 나오지 않는다(D-25). 서류 파일 폴더 규칙(`이력서_YYYYMMDD.pdf`)은 지난 기록용으로 그대로다.

### 5.6 서류 키트 (`/resume?tab=kit`) — 3단계, 기획서 7.11, D-27

맞춤 이력서(3.4)의 재료. 사용자가 직접 관리하는 공고 맞춤 가이드, 작성 규칙, 마스터스토리(사실 원본), 직무별 기본 이력서·경력기술서 md, (선택) PDF 스타일을 **브라우저에서 골라 올린** 사본이다. 앱은 원본 폴더를 읽지 않는다.

```
서류 키트   v5 · 11/20 15:30 올림                                   [키트 파일 올리기]
파일   가이드 · 작성 규칙 · 마스터스토리 · 이력서(백엔드) · 경력기술서(백엔드) · 이력서(FDE) · 경력기술서(FDE) · PDF 스타일

읽은 내용
  직무       백엔드(기본 B1) · FDE(기본 F1)
  프로필     표: id / 이름 / 공고 단어 / 자기소개 후보 / 핵심 역량·주요 성과·장 순서 / 개인 프로젝트
  추가 조정   백엔드 n · FDE n      허용 범위 n줄      체크리스트 n개
  부품 짝     표: 번호표 이름 → 기본 서류에서 찾은 제목(직무·문서별)        ← 사용자가 맞는지 눈으로 확인

키트 기록   v5 11/20 · v4 11/19(오류 2) …
```

| 요소 | 동작 |
|---|---|
| `[키트 파일 올리기]` | 파일 여러 개 선택(md 10개까지 + 스타일 1개, 파일당 1MB). 올리면 새 키트 버전이 생기고 바로 읽은 결과를 보인다. 이전 버전은 지우지 않는다(옛 맞춤본이 그 키트를 쓴다) |
| 파일 역할 | 이름·내용으로 정한다(가이드, 작성 규칙, 마스터스토리, 가이드 표에 적힌 기본 서류, 스타일). 역할을 모르는 파일은 오류 |
| 오류 | 빨간 목록: 파일 · 위치(구획 이름·줄) · 문장. 예 "가이드 '번호표'에서 FDE 이력서 줄을 찾지 못했습니다", "백엔드 이력서의 핵심 역량은 번호표에 4개인데 5개입니다". 오류가 있는 키트로는 맞춤본을 만들지 않는다 |
| 키트가 없음 | "아직 서류 키트가 없습니다. 가이드·작성 규칙·마스터스토리·기본 서류 md를 한 번에 골라 올리세요." |
| 키트 형식 | 접힌 도움말: 앱이 가이드에서 찾는 구획 이름과 표 열(계획 "서류 키트 형식") |

- 원본을 고치면 고친 파일을 포함해 **키트 전체를 다시 올린다**(어느 파일이 바뀌었는지 앱은 모른다). 같은 내용이면 "바뀐 파일이 없습니다"로 새 버전을 만들지 않는다(sha256 비교).
- 키트 파일 내용(자기소개·경력·수치)은 이 화면에 그대로 펼쳐 보이지 않는다. 구조(이름·개수·순서)만 보인다.

## 6. 기존 지원 내역 가져오기 `/import`

**목적**: 각 사이트 "지원 현황" 화면을 복사해 넣어, 이미 지원한 기록을 한 번에 등록한다(처음부터 중복 검사가 작동하도록).

### 6.1 입력 단계

| 요소 | 동작 |
|---|---|
| 사이트 선택 | 리멤버 / 원티드 / 그룹바이 / 잡코리아 / 홈페이지 지원 / 기타 (사이트를 모르면 행마다 정함) |
| 텍스트 붙여넣기 | 지원 현황 화면을 전체 선택해 복사한 텍스트 |
| 캡처 이미지 올리기 | 여러 장 가능 |
| `[추출하기]` | 텍스트·이미지 둘 다 없으면 비활성. 누르면 작업 진행 표시("지원 내역을 표로 정리 중…") |
| `[표에 직접 입력]` | AI 없이 검토 단계를 빈 행 1개로 연다(`/import?manual=1&site=<사이트>`). 행 사이트 = 고른 사이트. 사이트를 안 골랐거나 "모름"이면 비활성 + "직접 입력하려면 사이트를 고르세요". 그룹바이처럼 메일·화면 복사가 없는 지난 기록용 |

### 6.2 검토 단계

```
☑ 회사        포지션        사이트   지원일       상태      
☑ 토스        Server Dev   원티드   2025-10-03   서류합격           [삭제]
☐ 당근        Backend      원티드   2025-09-01   지원     이미 있음  [삭제]
☑ (비어 있음) Frontend     원티드   2025-08-20   지원               [삭제]   ← 빈 칸 강조
[+ 행 추가]                                                    [2건 등록]
```

| 요소 | 동작 |
|---|---|
| 배치 | 행마다 두 줄: 1줄 체크·회사·포지션·사이트·지원일·상태·안내·삭제, 2줄 서류 3개(가로) + 메모. 폭 1024에서도 가로 스크롤 없이 모두 보인다. 회사·포지션은 길면 줄바꿈되며 칸 높이가 늘어난다(줄바꿈 키는 막음) |
| 행마다 | 회사·포지션·사이트(기타면 출처 이름 칸, 홈페이지 지원은 칸 없음)·지원일(달력으로 고름)·상태 모두 고칠 수 있음, `[삭제]` |
| 체크박스 | 등록할 행 선택 |
| "이미 있음" | 같은 회사 + 같은 지원일 기록이 이미 있으면 표시하고 기본 체크 해제(같은 내역을 두 번 가져올 때 대비) |
| 빈 칸 | 강조. 체크된 행에 빈 칸이 있으면 등록 불가 |
| `[+ 행 추가]` | 빈 행 추가(추출이 놓친 것 직접 입력) |
| `[N건 등록]` | 체크된 행만 등록 → "N건을 등록했습니다 → 대시보드" 알림. 등록된 기록은 공고 없이 "기록만" 상태. 같은 지원일 행은 표에서 위에 있던 행이 대시보드에서도 위에 온다(D-17) |
| `[처음부터]` | 검토 표를 버리고 입력 단계로 |
| 메모 칸 | 행마다 한 줄 입력(선택, 2000자까지). 등록하면 지원 기록 메모가 된다 |
| 서류 칸 | 이력서 / 경력기술서 / 포트폴리오 select 3개(선택). 종류 이름은 각 select 왼쪽에 라벨로 한 번만 쓰고(`이력서 [모름 ▾]`), 선택지는 `모름`·`없음`·`2026-10-17`처럼 짧게 쓴다. 선택지 순서: 이력서는 "모름" + 파일 날짜(늦은 순). 경력기술서·포트폴리오는 "모름" + "없음" + 파일 날짜(늦은 순). 지원일을 넣거나 고치면, 직접 고르지 않은 select는 "지원일과 같은 날이거나 앞선 가장 늦은 파일"로 다시 골라진다. 그런 파일이 없으면 이력서는 "모름", 경력기술서·포트폴리오는 "없음"(그 종류 파일이 폴더에 하나도 없으면 "모름"). 직접 고른 select는 날짜를 바꿔도 그대로. 저장되는 값은 파일 이름, "없음", 모름(빈 값) 중 하나(기획서 7.9) |
| 필수 칸 | 사이트, 회사, 포지션, 지원일(D-16). 지금 규칙과 같다 |

**직접 입력일 때만** (`?manual=1`)

| 요소 | 동작 |
|---|---|
| 머리말 | "사이트·회사·포지션·지원일은 꼭 채우세요. 서류는 지원일에 맞춰 자동으로 골라집니다." 단계 표시 "2. 검토" |
| "이미 있음" | 같은 회사 + 같은 지원일 + 같은 포지션(기존 기록이 `(포지션 미상)`이면 포함)이면 표시하고 체크 해제 |
| "같은 날 기록 있음" | 같은 회사 + 같은 지원일인데 포지션이 다르면 흐린 표시만 하고 체크는 유지 |
| `[+ 행 추가]` | 새 행 사이트 = 마지막 행의 사이트, 지원일 빈 칸 |
| 서류 파일이 0개 | 표 위에 "서류 파일이 없어 서류는 모두 '모름'입니다 → 서류 파일" 링크(파일이 없으면 "없음"도 자동으로 고르지 않는다. 직접 "없음"을 고를 수는 있다) |

## 7. 사이트 반영 체크리스트 `/sync` **(5단계)**

**목적**: 기본 이력서를 고친 뒤 4개 사이트 이력서에 손으로 옮길 내용을 사이트별로 정리해 보여주고, 반영했는지 체크한다.

```
리멤버                         원티드                        그룹바이        잡코리아
기본 이력서 v1 → v3 반영        ✔ 반영됨                       정리 중…        ⚠ 실패
 항목       할 일  붙여넣을 문구                                               [다시 만들기]
 한 줄 소개  수정   "결제 …" [복사]
 경력 A사    추가   "…"      [복사]
 [이 사이트 반영 완료]

최근 완료   원티드 · v2 → v3 · 11/16 15:10
```

| 카드 상태 | 표시 | 버튼 |
|---|---|---|
| 정리 중 | "반영할 내용 정리 중…" | 없음 |
| 준비됨 | 제목 "기본 이력서 v1 → v3 반영"(그 사이트에 마지막으로 반영한 버전 → 현재 버전). 항목 표: 항목 / 할 일 / 붙여넣을 문구 / 메모 | 문구마다 `[복사]`, `[이 사이트 반영 완료]` |
| 실패 | 오류 문구 | `[다시 만들기]` |
| 반영할 것 없음 | "최신 상태입니다" | 없음 |

| 동작 | 설명 |
|---|---|
| 반영 전 다시 저장 | 사이트마다 마지막 반영 버전부터 최신 버전까지 **하나로 합쳐서** 다시 정리(예: 원티드만 v2를 반영했다면 원티드는 v2→v3, 나머지는 v1→v3) |
| 메모만 바꾼 저장 | 내용이 같으면 새 체크리스트를 만들지 않음 |
| `[이 사이트 반영 완료]` | 그 카드를 "반영됨"으로, 내비게이션 배지 1 감소 |
| 모두 반영 | "모든 사이트에 반영되었습니다" |
| 최근 완료 목록 | 사이트 · 버전 범위 · 완료 시각 |

### 10.1 결과 분류와 비율

모든 숫자는 지원 기록 하나를 아래 다섯 결과 중 하나로 나눠 센다. 위에서부터 처음 맞는 것을 고른다.

| 결과 | 조건 |
|---|---|
| 서류 통과 | 서류합격을 거침. 지금 상태 또는 이력에 서류합격, 과제·코딩테스트, 면접, 최종합격 중 하나가 있다. 지금 상태가 지원이면 통과가 아니다 |
| 지원취소 | 지금 상태 지원취소 |
| 불합격 | 지금 상태 불합격 |
| 대기 | 지금 상태 지원, 지원 후 30일 안 됨 |
| 무응답 | 지금 상태 지원, 지원 후 30일 이상 |

- 서류 통과율 = 통과 ÷ (통과 + 불합격 + 무응답). 대기와 지원취소는 분모에서 뺀다.
- 판정 기준 통과율(참고) = 통과 ÷ (통과 + 불합격)
- 무응답 비율 = 무응답 ÷ (통과 + 불합격 + 무응답)
- 비율은 소수 한 자리로 쓰고, 옆에 분자/분모를 쓴다. 예: `1.9% (9/469)`

| 분모 | 비율 칸 표시 |
|---|---|
| 0 | "–" + 보조 글자 "결과 없음" |
| 1~4 | "표본 부족 (n=3)" (비율 숨김) |
| 5~19 | `12.5% (1/8)` + 회색 "표본 적음" 배지 |
| 20 이상 | `1.9% (9/469)` |

### 10.2 필터·전환

모두 주소에 남는다. 뒤로 가기나 새로고침을 해도 유지된다.

| 요소 | 값 | 주소 |
|---|---|---|
| `[기간 ▾]` | 전체 / 최근 3개월 / 최근 1년 / 직접 지정(시작일~종료일) | `?period=3m\|1y\|custom&from=&to=` |
| `[사이트 ▾]` | 전체 / 리멤버 / 원티드 / 그룹바이 / 잡코리아 / 홈페이지 지원 / 기타 | `?site=` |
| `[월별 \| 연별]` | 기간별 그래프 단위 | `?unit=year` |
| `[개수 \| 비율]` | 기간별 그래프 막대 모양(비율 = 100% 누적) | `?mode=ratio` |
| `[이력서 \| 경력기술서 \| 포트폴리오]` | 서류 버전별 종류 | `?doc=career\|portfolio` |

- 기본값(전체, 월별, 개수, 이력서)은 주소에서 생략한다.
- 검색창과 상태 필터는 없다. 상태로 거르면 통과율이 0% 아니면 100%가 되기 때문이다.

### 10.3 보여주는 데이터

| 영역 | 내용 |
|---|---|
| 안내 줄 | "지원 후 30일이 지나도 '지원' 상태인 기록은 무응답으로 셉니다. 기간은 지원일 기준입니다." |
| 요약 카드 6개 | 아래 표 |
| **맞춤 이력서 효과** (3단계, D-24) | 요약 카드 바로 아래 전체 폭 카드. 필터 안에서 맞춤본으로 낸 가장 이른 지원일부터의 지원만 두 줄로 비교한다: "맞춤 이력서"(제출 서류의 이력서가 맞춤본) / "맞춤 안 함"(그 밖 전부). 가로 막대(길이 = 지원 수, 진한 부분 = 통과) + 표(구분 / 지원 / 통과 / 불합격 / 무응답 / 대기 / 서류 통과율, 표본 표시 10.1). 카드 아래 고정 문구: "{YYYY-MM-DD}(맞춤본을 처음 낸 날)부터의 지원만 비교합니다. 지원 후 30일이 안 된 지원은 대기로 빠지므로, 처음 몇 주는 표본이 적습니다." 맞춤본 기록이 없으면 막대·표 대신 "아직 맞춤 이력서로 낸 지원이 없습니다. 지원 완료 때 제출 서류의 이력서를 '맞춤 이력서'로 고르면 여기서 비교됩니다." **프로필별**(D-29): 같은 카드 아래쪽 표. 프로필 / 지원 / 통과 / 불합격 / 무응답 / 대기 / 서류 통과율 / 그중 맞춤(맞춤본 수). 맞춤본과 기본 서류 기록을 모두 프로필로 센다(기간 제한 없음, 필터만 적용). 프로필 기록이 없으면 "프로필이 기록된 지원이 없습니다." |
| 기간별 지원과 결과 | 세로 누적 막대(아래부터 서류 통과·불합격·무응답·대기). 지원취소는 표에만 넣는다. 막대 위에 서류 통과율(표본 부족이면 "–")을 쓴다. 기간의 첫 단위부터 마지막 단위까지 빈칸 없이(0건 달도 자리 있음). 오늘이 속한 달·해는 x축 이름 아래 "(진행 중)". 막대에 마우스를 올리면 "2026-10 · 통과 1 · 불합격 41 · 무응답 0 · 대기 0". 아래 "표로 보기"(접힘) |
| 서류 버전별 | 고른 종류의 버전마다 가로 막대(길이 = 지원 수, 진한 부분 = 통과)와 비율. 표 열: 버전 / 지원 / 통과 / 불합격 / 무응답 / 대기 / 쓴 기간(첫~마지막 지원일) / 서류 통과율. 이력서 순서: **맞춤 이력서**(3단계, 보조 글자 "공고마다 맞춘 이력서") → 기본 서류 {직무}(3단계) → 기본 v{n}(번호 큰 순) → 이력서 파일(날짜 늦은 순, "이력서 2026-11-02") → 모름. 경력기술서·포트폴리오는 맞춤본으로 낸 기록도 그 종류의 파일 값으로 센다. 경력기술서·포트폴리오: 파일(날짜 늦은 순) → **없음** → 모름. 보조 글자: 이력서 "모름" 아래 "버전 파일보다 앞선 지원", 경력기술서·포트폴리오 "없음" 아래 "내지 않은 지원", "모름" 아래 "제출 서류 기록 없음". "없음"도 다른 묶음처럼 막대·비율을 보인다(냈을 때와 안 냈을 때를 비교할 수 있게). 카드 아래 고정 문구: "버전마다 쓴 기간과 사이트가 다릅니다. 기간·사이트 필터로 조건을 맞춰 비교하세요." |
| 사이트별 | 사이트마다 가로 막대(사이트 색), 비율. 표 열: 사이트 / 지원 / 통과 / 불합격 / 무응답 / 대기 / 서류 통과율 / 무응답 비율. 0건 사이트는 숨김. 사이트 필터가 걸리면 그 한 줄 + 제목 옆 "사이트 필터 적용 중" 배지 |
| 단계별 흐름 | 지원(전체 − 통과 못 한 지원취소) → 서류 통과 → 과제·코딩테스트 → 면접 → 최종합격을 거친 수, 괄호에 앞 단계 대비 %. 과제·코딩테스트 줄은 들여 쓰고 이름 옆에 보조 글자 "(거치지 않을 수 있음)". 과제와 면접의 %는 둘 다 서류 통과 대비다(과제 없이 면접으로 가는 기록이 있어 면접 수가 과제 수보다 클 수 있다) |
| 요일별 | 월~일 세로 막대(지원 수, 통과 부분 진하게) + 표(요일 / 지원 / 통과 / 서류 통과율) |
| 용어 설명(접힘) | 10.1의 결과 다섯 가지, 비율 세 가지, 표본 표시 |

### 10.4 상황별 표시

| 상황 | 표시 |
|---|---|
| 지원 기록이 하나도 없음 | 카드·그래프 대신 "아직 지원 기록이 없습니다. 지원 기록이 쌓이면 여기에 통계가 보입니다." + `[공고 등록]` + "이미 지원한 내역이 있다면 → 가져오기" |
| 필터 결과 0건 | "이 기간·사이트에 지원 기록이 없습니다." + `[필터 지우기]`(→ `/stats`) |
| 서류 통과 0건 | 카드 아래 한 줄: "서류합격·면접 연락을 받았다면 대시보드에서 상태를 바꿔 주세요. 통계가 정확해집니다." |
| 고른 서류 종류의 파일 기록이 없음 | 묶음이 "모름" 하나뿐이면 그 한 줄 + "이 종류의 제출 서류 기록이 없습니다". "없음" 묶음이 있으면 이 문구를 쓰지 않는다 |
| 분모가 작음 | 10.1 표본 표시 |

### 10.5 만들지 않는 것

- 서류 통과까지 걸린 일수(D-21)
- 시간대별(D-17)
- 같은 회사 재지원, 적합도별, 포지션 키워드별
- 내보내기, 상태 일괄 변경
