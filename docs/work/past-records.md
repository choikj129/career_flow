# past-records — 지난 지원 기록 직접 입력 + 제출 서류 파일

- 요청: 지난 지원 기록을 직접 입력한다(필수: 사이트·회사·포지션·지원일, 선택: 메모·이력서·경력기술서·포트폴리오 파일). 서류는 `(이력서|경력기술서|포트폴리오)_YYYYMMDD.pdf` 파일이고 이름의 날짜가 버전이다. 지원 기록에는 파일 이름만 저장하고 [보기]로 그 파일을 연다. 종류마다 가장 이른 파일보다 앞선 지원은 "모름". 메일(원티드·잡코리아·리멤버) 지난 기록은 앱 기능이 아니라 메인 세션이 한 번 DB로 옮겼다. 지원 기록에 화면에 안 보이는 정렬용 일시를 두고, 같은 날 기록이 시간 순으로 정렬되게 한다 (2026-11-19, D-15·D-16·D-17 결정 반영)
- 브랜치: `feat/past-records`
- 상태: 설계 완료(재설계 3회 반영), 사용자 검토 대기
- 관련 결정: D-15(제출 서류는 파일 이름만 참조, 보기 제공), D-16(사이트·회사·포지션·지원일 모두 필수), D-17(정렬 전용 일시 칸) — 모두 결정됨

## 1. 설계 (product-planner)

### 검토할 것 (이 절만 읽고 승인할 수 있게)

1. **직접 입력**: 가져오기 화면의 [표에 직접 입력] → AI 없이 빈 표. 필수 사이트·회사·포지션·지원일, 선택 메모·서류 파일 3종. 같은 회사·날짜·포지션 기록이 있으면 "이미 있음"으로 체크 해제.
2. **제출 서류 파일**: `data/documents/`의 `이력서_YYYYMMDD.pdf` 형식 파일을 폴더에서 바로 읽는다(등록 절차·테이블 없음). 지원 기록에는 파일 이름만 저장. 지원일과 같은 날이거나 앞선 가장 최근 파일이 자동 선택되고, 종류마다 가장 이른 파일보다 앞서면 그 종류만 "모름".
3. **[보기]**: 대시보드 기록 펼침과 공고 상세 지원 기록 탭에서 PDF를 새 탭으로 연다. 폴더 밖 파일은 열지 않는다.
4. **서류 파일 탭**(기본 이력서 화면): 폴더 목록 + [보기] + [메모의 제출 서류 옮기기](메일·그룹바이 기록 메모 둘째 줄을 제출 서류 칸으로 옮김, 첫 줄은 남김).
5. **같은 날 정렬**: 화면에 안 보이는 정렬용 일시를 둔다. 정렬은 지원일 → 일시 → 등록 순. 메일 기록은 수신 시각, 그룹바이는 사용자가 쓴 표 순서로 한 번 채운다(백업 → 미리 보기 → 실행, 메인 세션이 확인 후).
6. **상태 필터**: "서류합격"을 고르면 서류합격을 거친 기록이 모두 나온다(그 뒤 면접·불합격·지원취소 포함). 면접·최종합격도 같다. 지원·불합격·지원취소는 지금 상태. 단, 상태가 지금 "지원"이면 거친 것으로 치지 않는다(잘못 누른 것 되돌림).
7. **함께 바뀌는 것**: 요약 줄의 서류합격·면접·최종합격 수와 서류 통과율도 "거친 단계" 기준이 된다(서류합격 뒤 불합격도 통과로 셈). **상태별 보드의 칸은 지금 상태 그대로**(카드를 끌어 상태를 바꿔야 하므로).
8. **만들지 않는 것**: 메일 자동 수집, 앱의 `D:\` 접근, PDF 올리기·내용 읽기, 정렬용 일시 표시, 수정 창에서 서류 고치기(3단계). AI 호출 0회.

계획 본문: [docs/plans/phase-2-past-records.md](../plans/phase-2-past-records.md). 아래는 상세 요약이다.

### 확정된 사용자 결정 (2026-11-19)

- 메일 지난 기록은 앱 기능이 아니다. 메인 세션이 일회성으로 DB에 넣었다(메일 452건 + 그룹바이).
- 서류 종류는 이력서 / 경력기술서 / 포트폴리오. 자기소개서 없음. 직무별 변형본 무시.
- 유효한 파일은 `(이력서|경력기술서|포트폴리오)_YYYYMMDD.pdf`만. 버전 날짜 = 이름의 날짜.
- 앱은 `D:\`를 읽지 않는다. 파일 7개를 `data/documents/<resume|career|portfolio>/`에 원래 이름으로 복사했다(완료). 날짜: 이력서 2026-09-05·10-17·11-02 / 경력기술서 2026-10-17·11-02 / 포트폴리오 2026-07-22·10-17.
- **D-15**: 지원 기록은 종류별 **파일 이름만** 참조하고, [보기]를 누르면 그 경로의 파일을 보여 준다.
- **D-16**: 직접 입력 필수 칸은 사이트·회사·포지션·지원일. 기존 가져오기 동작은 그대로.
- **D-17**: 일시 칸을 더하되 화면에는 보이지 않고 정렬에만 쓴다. 그룹바이는 사용자가 시간 순(최신이 위)으로 적은 표가 있으니 그 순서대로 정렬되게 한다.

### 목표와 범위

1. **직접 입력**: `/import`의 `[표에 직접 입력]` → AI 없이 빈 검토 표. 필수 사이트·회사·포지션·지원일, 선택 메모·서류 파일 3종. 여러 행 한 번에 등록.
2. **서류 파일 목록**: 테이블 없이 `data/documents/` 폴더를 읽어 이름 규칙으로 바로 얻는다. 등록 절차 없음. 새 파일은 폴더에 넣기만 하면 된다.
3. **지원 기록 연결**: `applications.submitted_docs` JSON `{resume?, career?, portfolio?: 파일 이름 | null}`. 지원일로 자동 선택: **같은 날 포함**, 앞선 파일 중 가장 늦은 것. 종류마다 없으면 그 종류만 "모름".
4. **보기**: `GET /api/documents/[name]`이 이름 규칙 + 종류 폴더 안만 허용해 PDF를 inline으로 보낸다. 대시보드 기록만 행 펼침과 공고 상세 지원 기록 탭에 "제출 서류" 세 줄 + [보기]. 파일이 없어졌으면 "파일 없음".
5. **메모 이관**: 메모 둘째 줄 `제출 서류: 이력서 YYYY-MM-DD|모름 / 경력기술서 … / 포트폴리오 …`를 날짜 → 파일 이름(`이력서_YYYYMMDD.pdf`)으로 바꿔 `submitted_docs`에 넣고 그 줄을 지운다. 첫 줄(`메일 가져오기(원티드)` 등)은 남긴다. 폴더에 없는 파일이 있으면 건너뛴다. 재실행 안전.
6. **서류 파일 탭**: `/resume?tab=docs`에 폴더 내용 목록(종류별, 날짜, 사용 건수, [보기]) + 규칙 밖 파일 안내 + [메모의 제출 서류 옮기기].
7. **대시보드**: 라벨·"이력서별" 묶음에 이력서 파일 반영(기본 버전 → 이력서 파일 → 모름).
8. **정렬용 일시**(D-17, 계획 Task 5): `applications.applied_datetime`(KST ISO 고정 모양 `…+09:00`, nullable, 화면에 안 보임). 모든 지원 기록 목록의 기본 정렬은 지원일 ↓ → 일시 ↓(NULL은 같은 날 맨 뒤) → id ↓. 값: [지원 완료]는 저장 시각, 직접 입력·가져오기는 같은 지원일 안에서 표 위 행이 더 최근이 되도록 만든 값(`syntheticKstIso(appliedAt, rank)` = 12:00:00에서 rank초 뺀 값).
9. **일회성 채우기**(계획 Task 5 "일회성 실행 절차"): 메일 452건은 `data/backups/data-<site>[-n].txt`의 `UTC시각|회사|포지션`으로 채운다(키: 사이트·회사·포지션·지원일). 그룹바이 17건은 `data/groupby-history.md` 표 순서(최신이 위)로 같은 날 안의 정렬용 값을 만든다. 실제 시각이 아님을 스키마 주석과 기획서 10장에 적었다. developer가 `scripts/backfill-applied-datetime.ts`(`--dry-run` 있음)를 만들고, 메인 세션이 사용자 확인 후 백업을 만들고 실행한다.
10. **상태 필터 = 거친 단계**(계획 Task 6, 사용자 요청 2026-11-19): 서류합격·면접·최종합격 필터는 지금 상태가 그 단계 이후이거나 상태 이력에 그 단계 이상이 있는 기록. 지금 상태가 지원이면 제외. 지원·불합격·지원취소는 지금 상태. 상태별 보드 칸은 지금 상태 유지. 요약 줄 세 숫자와 서류 통과율도 거친 단계 기준(`reachedCounts` 추가, `byStatus` 합계는 그대로). 근거: 지금 필터는 `src/lib/search/dashboard.ts:43`에서 지금 상태만 비교한다.

### 만들지 않는 것

- 메일 파싱·가져오기 파일. 계속되는 자동 수집.
- 서류 버전 테이블, [폴더에서 찾기]·등록·삭제 절차.
- 앱이 데이터 폴더 밖(`D:\` 등)을 읽는 것. PDF 내용 읽기·구조화(`claude` 0회).
- 앱에서 PDF 올리기.
- 지원 기록 수정 창(3.10)에서 제출 서류 고치기 → 3단계 Task 4에 메모.
- 앞으로의 [지원 완료]에 서류 파일 기록.
- 필수 칸 규칙 변경(D-16: 지금 그대로).
- 정렬용 일시를 화면에 보이거나 고치는 기능(D-17).

### 데이터·화면·작업 흐름 변경

- **데이터**: `applications.submitted_docs`(JSON, nullable)와 `applications.applied_datetime`(text, nullable, 정렬 전용) 두 칸을 더한다. 마이그레이션 `submitted_docs`, `applied_datetime`. 새 테이블 없음. `submitted_resume`는 그대로(가져온 기록은 `{kind:'imported'}`).
- **테이블을 두지 않는 근거**: 종류·날짜는 파일 이름에 다 있고, (종류, 날짜) 하나가 파일 하나다. 저장할 추가 정보(메모·변형)가 없고, 폴더 7개 파일 읽기는 비용이 거의 없다. 테이블을 두면 폴더와 목록이 어긋날 수 있다(파일을 지웠는데 목록에 남음). 사용 건수는 `submitted_docs`에서 센다.
- **함수**(시그니처는 계획 Task 1~3):
  - `src/lib/documents/files.ts`: `parseDocFileName`, `docFileName`, `docLabel`, `pickDocFile(kind, appliedAt, files): string | null`, `pickDocs`, `isDocsForKind`, `formatDocsNote`, `parseDocsNote`
  - `src/lib/documents/folder.ts`: `listDocFiles(dir?)`, `resolveDocPath(fileName, dir?)`, `docFileExists`
  - `src/lib/documents/migrate.ts`: `migrateDocsFromNotes(dir?, db?)`, `countDocsNotesPending(db?)`
  - `src/lib/applications/import-review.ts`: `findExistingMatches(rows, db?): ('same'|'same_day'|'none')[]`
  - `bulkCreateApplications` 행에 `notes?`, `submittedDocs?`(파일 존재 확인)
- **보안**: 보기 라우트와 저장 검증 모두 `/^(이력서|경력기술서|포트폴리오)_\d{8}\.pdf$/` + 실제 날짜 + 종류 폴더 안 경로 확인. `X-Content-Type-Options: nosniff`, `Cache-Control: no-store`. 서버는 `127.0.0.1` 전용.
- **화면 문구**: screens.md 5.5(서류 파일 탭, 제출 서류 표시), 6.1·6.2(직접 입력).
