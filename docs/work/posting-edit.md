## 1. 설계 (PM)

### 1) 공고 등록 때 회사명·포지션 직접 입력

- 공고 등록 화면(`NewPostingForm`): 링크 칸 아래에 선택 입력 두 칸 "회사명 (선택)", "포지션 (선택)". 비우면 지금처럼 분석이 채운다.
- 저장: 등록할 때 회사명이 있으면 기존 회사 찾기·만들기(`findOrCreateCompany`, 같은 이름 규칙·별칭 사용)로 공고에 연결한다. 포지션이 있으면 `positionTitle`에 저장한다.
- 분석이 덮어쓰지 않게: 지금 `saveAnalysis`는 회사가 이미 연결돼 있으면 그대로 둔다(유지). 포지션은 사용자가 넣은 값을 지키기 위해 **공고에 포지션이 이미 있으면 분석이 바꾸지 않는다**(다시 분석해도 그대로). 새 열·표는 만들지 않는다.
  - 영향: 앞으로는 AI가 처음 채운 포지션도 다시 분석으로 바뀌지 않는다. 고치려면 아래 상세 화면 수정으로.
- 이미 등록한 공고도 고칠 수 있게 상세 화면 머리(회사 이름·포지션 제목 옆)에 작은 [수정] → 창에서 회사명·포지션 두 칸. 회사명을 바꾸면 그 이름의 회사를 찾거나 만들어 이 공고를 연결한다(기존 회사·다른 공고·지원 기록은 그대로). 지원 기록이 있는 공고의 회사 변경은 그 지원 기록의 회사도 같이 바뀌는지 확인하고(지원 기록이 공고를 통해 회사를 보는 구조면 자동), 아니면 공고만 바꾼다고 창에 적는다. 기존 [회사 연결 변경](별칭·합치기)은 그대로 둔다.
- 입력 검사: 앞뒤 공백 제거, 빈 값이면 그 칸은 바꾸지 않음(등록 때) / 비울 수 없음(수정 창), 회사명 100자·포지션 200자 이하.

### 2) 분석한 공고 목록에서 삭제

- `/postings/analyzed` 표의 각 줄 끝에 작은 [삭제] 버튼(분석 중·실패 줄 포함). 누르면 지금 상세 화면과 같은 확인 창("이 공고와 분석 결과를 삭제합니다. 되돌릴 수 없습니다.") → 삭제 후 **목록에 그대로 머문다**(상세 화면 삭제는 지금처럼 대시보드로).
- 줄 전체가 클릭하면 상세로 가는 줄(`ClickableRow`)이라, 버튼 클릭이 줄 이동을 일으키지 않게 한다.
- 이 목록은 지원 기록이 없는 공고만 보이므로 삭제 조건(지원 기록 없는 공고만)과 맞다. 서버 쪽 검사는 기존 `deletePosting` 그대로.
- 분석이 진행 중인 공고 삭제: 기존 동작 확인(작업이 남아 문제가 되면 진행 중이면 버튼 비활성 + 이유 title).

### 3) PDF 브라우저 대체 실행

- `src/lib/pdf/render.ts`: `chromium.launch()`가 "실행 파일 없음" 등으로 실패하면 설치된 Chrome → Edge(`channel: 'chrome'`, `'msedge'`)로 headless 실행을 한 번씩 더 시도한다. 셋 다 실패하면 첫 오류를 던진다. 기존 `launchHeaded`(로그인 창)와 같은 순서 규칙을 참고하되 headless로.
- 실패해 대체로 넘어갈 때 `console.warn` 한 줄(경로·사유만).
- 같은 잠금(`acquireBrowserLock`) 안에서. Playwright 실행 위치 제한 규칙(`browser.ts`·`render.ts`만) 그대로.
