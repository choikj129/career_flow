# Git: 완료된 작업은 알아서 커밋·병합

원격은 `origin` = `https://github.com/choikj129/career_flow.git`이다(2026-11-19 연결). 커밋·병합은 로컬에서 하고, **push는 매번 사용자에게 묻는다.** 커밋 작성자 이메일은 GitHub 비공개용 주소(`87593382+choikj129@users.noreply.github.com`)를 쓴다(D-12).

## 묻지 않고 진행하는 것

작업 단위(계획의 Task 묶음, 결정 반영, 리뷰 수정, 문서 작업)가 **완전히 끝났으면** 사용자에게 묻지 않고 커밋하고 `main`에 병합한다.

"완전히 끝났다"는 아래가 모두 맞는 상태다.

- 코드 작업이면 다음 명령이 모두 실패 0이다.
  - `npm test`
  - `npm run test:e2e`(화면에 영향이 있을 때)
  - `npm run lint`
  - `npx next typegen` 후 `npx tsc --noEmit`
  - `npm run build`
- 마지막 검증(그 작업에 부른 검증 에이전트들을 합친 결과)에 "고쳐야 할 목록"의 필수 항목이 남아 있지 않다. 리뷰를 하지 않은 작은 수정이면 위 검사만으로 충분하다.
- 그 작업을 막는 열린 결정(`docs/decisions.md`의 "정할 것")이 없다.
- 더 고칠 것 없이 지금 버전 그대로 끝난 상태다. 이어서 할 일이 남은 중간 상태는 커밋만 하고 병합하지 않는다.

## 진행 방법

- 코드 작업은 `feat/<주제>` 또는 `fix/<주제>` 브랜치에서 한다.
- 커밋 메시지는 `feat:`, `fix:`, `test:`, `docs:`, `chore:`, `perf:`, `refactor:` 중 하나로 시작한다.
- 커밋은 경로를 지정해서 한다. `git add -A`, `git add .`는 쓰지 않는다.
- `data/`, `data-*/`, `.env*`, 인증 정보, 개인 이력서 파일은 절대 커밋하지 않는다.
- 병합 방법:
  - `main`으로 옮긴 뒤 `git merge --no-ff <브랜치>`로 병합한다.
  - 병합한 `main`에서 `npm test`를 한 번 더 돌린다.
  - 통과하면 병합한 브랜치를 지운다(`git branch -d`).
- 끝나면 무엇을 커밋·병합했는지 사용자에게 한두 줄로 알린다.

## 멈추고 물을 것

- 병합 충돌이 났을 때
- 테스트·검사가 실패하거나, 리뷰 필수 항목이 남았을 때
- 되돌리기 어려운 작업:
  - `push`(원격이 생기더라도 push는 묻는다)
  - `--force`, `reset --hard`
  - 이미 병합한 커밋을 고치는 rebase
  - 브랜치를 강제로 지우는 것(`-D`)
- 사용자가 작업 중인 것으로 보이는, 내가 만들지 않은 변경이 작업 트리에 있을 때

## 서브에이전트

- developer는 작업 브랜치에서 커밋만 하고, `main` 병합과 브랜치 삭제는 하지 않는다.
- 병합은 검증을 확인한 메인 세션이 이 규칙대로 한다.
