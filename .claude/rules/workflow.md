# 서브에이전트 워크플로우

새 기능, 다음 구현 단계, 큰 변경은 `/feature-workflow` 스킬(`.claude/skills/feature-workflow/SKILL.md`)로 진행한다.

```
product-planner(설계) → 사용자 검토 → developer(개발) → code-reviewer(검증)
                                          ↑                │ 수정 필요: 최대 2회 되돌림
                                          └────────────────┘
어느 단계든: 결정 필요 → 멈추고 사용자에게 묻기 / 설계 필요 → planner로 되돌리기 / 해결 불가 → 실패 사유 명시
```

- 서브에이전트끼리는 직접 부르지 못한다. 전달, 사용자 확인, 반복 횟수 관리는 메인 세션이 한다.
- 단계 사이에 넘기는 내용은 작업 기록 `docs/work/<작업 이름>.md`에 모은다.

## 보고서 끝의 상태 블록 (세 에이전트 공통)

모든 서브에이전트 보고서의 **마지막**에 아래 블록을 그대로 쓴다. 메인 세션은 이 블록으로 다음 단계를 정한다.

```
## 상태
- 결과: <아래 값 중 하나>
- 이유: <한 줄>
- 다음에 넘길 것: <다음 단계가 꼭 알아야 할 것. 없으면 "없음">
- 정할 것: <D-번호 초안 목록. 없으면 "없음">
- 설계 필요: <설계가 필요한 부분과 근거. 없으면 "없음">
- 실패 사유: <결과가 "실패"일 때만. 무엇이, 실제 출력, 원인, 시도한 것>
```

| 에이전트 | "결과"에 쓸 수 있는 값 |
|---|---|
| product-planner | `설계 완료` · `결정 필요` |
| developer | `완료` · `결정 필요` · `설계 필요` · `실패` |
| code-reviewer | `통과` · `수정 필요` · `결정 필요` · `설계 필요` |

- `결정 필요`: 필수·중요 결정 없이는 그 부분을 진행할 수 없다(`.claude/rules/ask-first.md`). 결정과 상관없는 부분은 끝내고 보고한다.
- `설계 필요`: 승인된 설계가 틀렸거나 빠져 있다. 구현만 고쳐서는 요구를 맞출 수 없다. 작은 구현 선택은 여기에 해당하지 않는다.
- `실패`: 시도했지만 해결하지 못했다. 사유를 정확히 쓴다. 추측은 추측이라고 표시한다.
- code-reviewer의 `수정 필요`는 "고쳐야 할 목록"에 **필수** 항목이 하나라도 있을 때만 쓴다. 권장·사소 항목만 남으면 `통과`로 쓰고, 목록은 그대로 남긴다.
