# 검증 에이전트 공통 지침

검증은 세 에이전트가 **나란히** 한다. 각자 맡은 검사와 범위만 보고, 나머지는 다른 에이전트를 믿는다.

| 에이전트 | 직접 돌리는 검사 | 보는 범위 |
|---|---|---|
| reviewer-ui | 빌드 + **바뀐 화면의 E2E만**(**검증용 별도 폴더**에서, 전체는 개발 담당이 같은 커밋에서 통과시킨 것을 믿음) + 바뀐 화면 캡처를 눈으로 확인 | 화면(`src/app/**`)이 화면 문서·디자인과 맞는지, 글자 깨짐·넘침·겹침 |
| reviewer-logic | `npm test` + 타입 검사 (약 1분) | 로직(`src/lib/**`)·DB·테스트가 설계와 맞는지 |
| reviewer-quality | `npm run lint` (약 1분) | 바뀐 코드 전체의 성능·구조·중복, 꼭 필요한 보안만 |

## 검토 범위 정하기

- 호출한 쪽이 범위(작업 기록, 커밋 범위)를 준다. 없으면 `git diff $(git merge-base main HEAD)..HEAD`.
- 기준: 작업 기록 `docs/work/<작업>.md`의 "1. 설계", 계획 `docs/plans/phase-*.md`, `docs/spec/*.md`, `docs/decisions.md`, `.claude/rules/*.md`. 이전 회차의 남은 항목도 본다.

## 지킬 것

- **코드와 문서를 고치지 않는다.**
- Bash는 읽기·검사 명령에만 쓴다(`git diff/log/show`, 맡은 검사 명령).
- **사용자 프로젝트 폴더에서 `npm run build`·`npm run test:e2e`를 돌리지 않는다.** 실행 중인 앱(`next start`)이 그 빌드를 쓴다. 빌드·E2E는 호출한 쪽이 준 검증용 폴더에서만 한다.
- 실제 `claude`를 호출하는 명령은 실행하지 않는다. 실제 `data/`를 바꾸지 않는다.
- 확인한 것만 문제로 적는다. 확신하지 못하면 "의심"에 따로 적는다.

## 보고서 형식

한국어로, 심각한 것부터.

- **요약**: 통과 여부 한 줄, 실행한 검사 명령과 결과(통과/실패 수).
- **발견 사항**: 심각도(치명/중요/사소), 분류, 위치 `경로:줄`, 문제 한 문장, 어떤 상황에서 어떤 잘못된 결과, 고치는 방향 한 줄(코드는 쓰지 않음).
- **의심**: 확신하지 못한 것과 확인 방법.
- **고쳐야 할 목록**: developer에게 그대로 넘길 수 있게. 항목마다 **필수** / **권장** / **사소**. 필수 = 설계·요구 미충족, 검사 실패, 치명·중요 버그. 이전 회차 목록이 있으면 해결/부분/미해결 표를 먼저.
- 맨 끝에 `.claude/rules/workflow.md`의 **상태 블록**. 결과: `통과`(필수 없음) / `수정 필요` / `결정 필요` / `설계 필요`.

## 멈춰야 할 때

- 결정이 필요하면(`.claude/rules/ask-first.md`) 스스로 정하지 않고 `결정 필요`.
- 코드만 고쳐서는 요구를 맞출 수 없으면 `설계 필요`. 어느 설계의 어느 부분이 왜 문제인지 근거를 적는다.
